# Perf pass: results (base -> cur)

Same harness, same machine, `docs/perf/data/*-base*.json` vs `*-cur*.json`. Absolute frame ms drift about +-1 ms with machine load between sessions: a re-run of Mežaparks low r=3 / r=30 on BOTH builds back to back gave 4.09 / 3.78 ms (base) vs 4.11 / 3.89 ms (cur), i.e. gameplay-zoom cost is unchanged; the early baseline rows (e.g. 1.3-2 ms) were taken on a quieter machine. Wide-view and build numbers moved far outside that noise.

## What was changed (each separately understandable)

1. **Distance LOD of props** (`src/world.js` `setViewDistance` + `THIN` table; hooks in `Game._syncVisuals` and `net/online.js` `_idleView`... same call next to `detail.update`). Beyond ~450 m camera distance people, bins, benches, cafe sets, bikes, scooters, parasols, flags thin out (gone by 1.0-1.4 km), lamps vanish by 2.2 km, parked cars / vans keep 40 % at 2.6 km, trees switch to the phone-tier crown above 850 m. Camera distance at hole radius 12 is 211 m, r=30 is 519 m, r=90 is 1.6 km, intro overview ~2 km+ (Centre). Object ids, fit, value, swallowing untouched (slots only spread with a coprime stride so thinning is even). Intro: **6.3-6.9 -> 3.2-3.6 ms desktop (Centre), 24-29 -> 7.8-9.2 ms Pixel 5 4x**; r=90 and max zoom-out -25..-45 %; calls 2048 -> 790, triangles 2.9-3.2 M -> 1.0-1.35 M. No change at r<=12; r=30 loses ~10 % of the people (3 px specks).
2. **`neighbourRef`** (`src/sights.js`): k-nearest by insertion instead of hypot + sort, exact same result (all wall colours / geometry buffers hash-identical, `scripts/perf/compare-world.mjs`). Sights treatment 160 -> ~15 ms desktop.
3. **`cornerHeights`** (`src/buildings.js`): per-triangle plan bbox reject. Building batch 108 -> 42 ms desktop (Centre), 433 -> 173 ms phone.
4. **Service worker** (`public/sw.js`, `src/meta/pwa.js`): install precaches only the shell; the page posts the played map's data URLs after load (3 s delay) and the worker caches those. Cold first visit on a district: **4.0-4.8 MB -> 1.6-2.5 MB** transferred in the first 6 s; Centre unchanged (3.16 MB); offline / instant repeat visit of the played map kept.
5. **Close-up ground repaint** (`src/ground.js`): squared-distance kernel, no per-pixel `fill`, polygon bbox cached on the ring. Repaint 21 -> ~8 ms per repaint (profile), `prep` LUT 41 -> 21 ms (desktop Centre) / 170 -> 78 ms phone.
6. Smaller: `attachStops` bbox skip (`src/traffic.js`), User Timing instrumentation (`src/perfMark.js`, spans `bd:*`, `__perf.simMs/renderMs/first`).

## Tried and reverted
- Coarser render chunks for tiny kinds (1923 -> 783 meshes): wide views as good as the LOD, but gameplay triangles +40-60 % (Purvciems r=30 0.76 -> 1.05 M low). Reverted for the LOD.
- Cropping the class-raster `drawImage` per ground tile: no gain (94.7 vs 96.1 ms). Reverted.

## Left alone, and why
- Sim (0.4-2.2 ms, traffic.update ~0.7): far movers at 1/3 rate would give ~0.3-0.5 ms but touches car-following consistency; the "8 holes < 4 ms" check passes now mostly on the lower gameplay render, honestly it is within noise of the old margin.
- Loader is still frozen during the (now shorter) build, 1.9 s longest task on the Pixel 5 profile: a Worker / async World is an architecture change.
- Water polygon point-in-polygon (`waterRoutes`, bridges) ~60 ms: needs a rasteriser that would have to reproduce routes (movers in the placement files) bit for bit.
- Data size (better codec, field pruning): see plan.md rows 11-12.
- Next best: far-mover throttling, deferring the skirt (50-190 ms on medium/high) until after the first frame, lazy second building geometry variant (shape vs flat), hole-radius-aware shadow caster list.
