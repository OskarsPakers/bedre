# Porting notes: sampled building parameters (L1 colours + L2 rhythm) into the game

Status: NOT ported. `src/` is untouched; everything below is derived from `tools/sampling/buildings-s.js` (the working, screenshot-tested copy; every change is marked `// [S]`) and from the line numbers of `src/buildings.js` as read on 2026-11-18 (the file is being edited by another agent, re-anchor by the quoted text, not by number). Decision taken by the owner: **L1 + L2 with confidence gating, no L3 bitmasks, centre map first**.

## 1. Data file (new, shipped)
`public/data/params.bin` (centre) / `public/data/<slug>/params.bin` (districts later), produced by `node tools/sampling/pack.mjs` from `tools/sampling/data/params-centrs.full.json`. Centre: 3 598 records, **49 218 B (13.7 B/building), 40.7 KB gzip** (json variant 413 KB / 76 KB gz, only for debugging). Format `BSP1`: `'BSP1'`, u32 count, then per building sorted by id: varint(id delta), u8 flags (b0 wall, b1 roof, b2 rhythm, b3 second wall, b4-6 roof class 0 tile / 1 zinc / 2 copper / 3 bitumen / 4 light, b7 shop band), u8 conf (2 bits each: wall, rhythm, roof), wall rgb (3), roof rgb (3), [second wall rgb (3) + u16 run bit mask], [rhythm: nF, floor height x0.05 m, bay x0.05 m, window width, height, sill (/255), ground band x0.1 m, cornice x0.05 m, glazing share (/255), trim rgb, flags (b0 string course, b1-3 pilaster)]. Only fields that passed the gate (wall conf >= 2, roof conf >= 2, rhythm conf >= 2) are present. `pack.mjs` decodes it back and checks (0 mismatches). Loader: a `loadParams()` next to `loadSights()` in `src/data.js` (line `data.shapes = await shapesP; data.sights = await sightsP; ...` in `loadCity`): fetch, parse into `Map(id -> record)` or typed arrays (`ids` sorted Uint32Array + record offsets), resolve `null` on failure (the game then looks exactly as today). Add `paramsUrl` to `tools/maps.mjs mapPaths()` and `CFG`.

## 2. `src/buildings.js` changes (anchors = quoted text)
1. **Vertex attributes** (class `GeoBuilder`, `constructor` / `vert()` / `geometry()`): two options, (a) as in the experiment: `aS1 aS2 aS3` (u8x4 each) + `aFac` (f32x2) = +20 B/vertex (buildings are ~1 M vertices on the centre: +20 MB GPU, too much for phones); **(b) recommended**: no per-vertex rhythm data, a **per-instance data texture keyed by the batch id** (see 3), and only `aFac` reduced to one float (bay coordinate along the facade, `wu / bayWidth`), i.e. +4 B/vertex. Both attribute sets must exist on EVERY geometry added to the BatchedMesh (zeros for roofs / props / non-sampled buildings), otherwise `addGeometry` throws.
2. **Facade runs** (new `src/facade.js`, copy of `tools/sampling/facade.js`, ~60 lines): `wallEdgesFlat(ring)`, `wallEdgesShape(S, rec)`, `facadeRuns(edges)`. Used in the two wall emitters: in `buildBuildingGeometry` the loop `for (let i = 0; i < n; i++) { const [x0, z0] = ring[i] ... b.quad([x0, 0, z0] ...` and in `buildShapeGeometry` the loop `while (p < end) { const len = L[p], y0 = L[p + 1] * inv; ...` with the edge counter `ek` (see the `// [S]` lines). They set the per-wall bay count so an integer number of bays fits the run (window spacing `len / round(len / sp)`), and floors are snapped so `nF` floors fit the wall height exactly (`U / nF`, `U = top - groundBand - 0.5 cornice`).
3. **Per-instance parameter texture** (recommended): RGBA8 texture, 2 texels per building (wall rgb + class, roof rgb + conf, then nF/fh/sp/ww/wh/wy/gh/co/gs/trim/flags in the next texels), width 4096, indexed by `vBid` (already available in the building fragment shader: `GLSL_BLD_VERT_DECL/SET` in `src/themeUniforms.js`, `vBid = getIndirectIndex(gl_DrawID)`). Colours then come from the texture (`diffuseColor.rgb = mix(vertexColour, texelColour, flag)`) instead of the vertex colour at build time, which has one big advantage: **the low quality tier keeps working and a data update needs no geometry rebuild**. Experiment path (simplest, what was screenshot-tested): colours are written into the vertex colours at build time exactly like the palette colours today (`wallCol` / `roofCol` / `pitchCol` / `flatCol`) and only the rhythm numbers use attributes.
4. **Material** `makeBuildingMaterial()`: replace the legacy window block gate `float wall = step(abs(vLN.y), 0.25) * mix(vWin.w, 0.9, strong);` by `... * (1.0 - sampled)` and insert the `SAMPLED_GLSL` chunk before `${GLSL_BLD_WINDOWS}` (see the file; it ends by writing `win`, `u`, `fy` so the night windows (`GLSL_BLD_WINDOWS`) light the sampled grid). Bump `customProgramCacheKey` (`'building-win6'`). L2 ground band is deliberately subtle in v2: faint plinth (0.05), glazing mix 0.5 with a light glass colour (v1 was a heavy dark stripe).
5. **Pass 2 of `buildBuildings`** (after `const T = it.sight ? treatmentFor(...)` and before `const nm = it.name || '';`): the `[S]` block that decides `useS`: sampled values apply when the record exists and the building is **not curated** (`it.rule` landmark rules or a tier-A sight key). Sights with a treatment `T` (tiers B / C) take sampled COLOURS (gate passed) but keep their facade style and features (`sampRhythm = !!SP.fh && !T`). Curated heroes keep theirs; if you later want them in: replace a curated colour only when the sample is conf 3 and within dE < 22 of it (`labDist` helper in the copy). For `rec` (shaped) buildings: the later `if (!T && rec.wallRGB) wallCol.setHex(rec.wallRGB)` and `pitchCol / flatCol` lines need the `[S]` guards (sampled wins), `if (!T && rec.style && STYLE_WIN[rec.style]) Object.assign(winParams, ...)` is skipped when the rhythm is sampled.
6. **RNG discipline**: the sampled override happens AFTER all `rng()` draws of the building, so every non-sampled building and every placement-dependent number (`fit`, `value`, `placements.json` signature) stays unchanged. Check `placements` (`world.js _checkPlacements`): it keys on building items, not colours, so no regeneration is needed.
7. **`it.wallCol` / `it.roofHex`** (used by flags, minimap, labels): set from the sampled colours (the `[S]` block does).

## 3. `src/sights.js` / `src/shapes.js` / `src/data.js`
* `src/sights.js treatmentFor`: unchanged. Interaction: tier-A sights (`TIER_A_BY_KEY`) stay fully curated (colour + style + features); tiers B / C: sampled colour + their own style / features (so a church or school is still told apart by form and features, not by a palette). If the owner prefers "important sights distinct by colour", skip sampled colours where `it.sight` exists (`const useS = !!SP && !it.sight && !curated`), one-line change.
* `src/shapes.js`: unchanged (the `COLOR_SLOT` / `renderClass` contract stays: **one roof colour per building** holds because `pitchCol` and `flatCol` are set to the same sampled colour; `node tools/detail/roof-report.mjs` reads the shapes file, not the params, so it must still report 0 violations; run it after the port to be sure). Optional later: write the sampled wall / roof colour into the existing `wallRGB` / `roofRGB` columns of `riga-shapes.bin.gz` at build time (`tools/detail/build-meshes.mjs`) for shaped buildings, but that covers only ~1/3 of the buildings, so the params file is still needed.
* `src/data.js`: `loadParams()` as above; pass `data.params` through `World` to `buildBuildings(data)`.

## 4. Roof rule
Class first (tile / zinc / copper / bitumen / light), then the colour from that class's range using the sample (tile L 38-52, a 16-30, b 14-30; copper green a -20..-6; zinc neutral L 48-66; bitumen L 34-46). Old Town prior (owner): ambiguous roofs with any warm texels are tile (evidence-only gives 43 % tile, with the prior 85 %; `OLDW` in `analyze2.mjs`): tell the owner this is a preference, the mesh and the orthophoto (17-25 % red) say most Riga roofs are grey. `zoneRoof()` (random 18 % / 90 % tile mix) becomes the fallback only for buildings without a gated sample.

## 5. Quality tiers, themes, tram
* **Low tier** (`rec.src === 3` builds a second flat `boxGeo` with `buildBuildingGeometry(...)`, swapped by `world.js setGeometryIdAt` at line ~113): pass the same `samp` object so the low tier gets the same colours; rhythm attributes are zeros-safe, windows may be dropped there. With the data-texture variant nothing changes (colour comes from the instance).
* **Evening / winter** (`uNight`, `uWinFrac`, `uSnow` in `themeUniforms.js`): albedo-like colours are theme-neutral by construction (the baked light is removed), the sampled block reuses `GLSL_BLD_WINDOWS` for lit windows (`win`, `u`, `fy`), and the snow roof tint uses `vLN.y` (unchanged). The sampled `trim` colour must be converted with `pow(rgb, 2.2)` like the experiment does.
* **Tram game** (`src/proto/tram/**` via `src/proto/shared/street-world.js` -> `World` -> `buildBuildings`): shares the renderer, so it gets the same data with no extra code; only `bootStreetWorld` must call the loader (it calls `loadCity`, which will load the params). Tram view distances are small: the L2 rhythm is the visible gain there (floors, shop band, cornice).
* **Hole camera**: colours + roofs matter most; rhythm is a bonus.

## 6. Risks / open items (honest)
* Baked-light removal is heuristic (pavement reference). Known-colour validation median dE 20 (n = 12), 0.57 chroma ratio: the result is paler and less saturated than the real plaster; do not promise "true colours".
* Rhythm: 60 % exact floors on a random sample after gating, 22 % off by one; stays a soft improvement (see README v2).
* Heroes (Opera, Stockmann, tier A) are not improved (by design): their curated palettes remain, and they are exactly the buildings seen first from the tram.
* The ids in the file are cadastre ids: a cadastre rebuild changes them; keep `meta.generated` of `riga.json` in the file header and refuse to apply a params file whose stamp differs.
