# tools/sampling: "sample, don't bake" (internal experiment)

Question: how good can the game's low-poly buildings look if **no photo texture is shipped** and only *parameters* per building (colours and a few facade numbers) are sampled from the city's reality mesh and fed to the game's own procedural building renderer?

Internal only. Nothing under `src/`, `public/`, `tools/realistic|detail` was touched; the game's modules are imported read-only. Port 5198 only. Reads the corridor cache `tools/.cache/realistic/` (no download was needed: **0 MB fetched**).

## Licensing, in one paragraph
* **Contain municipal imagery (local only, git-ignored, never ship):** `tools/.cache/sampling/rect/*.png` (rectified facades, 27 MB), `tools/.cache/sampling/roof/*.png` (rectified roofs, 6 MB), and the review/comparison screenshots that show the real mesh (`scripts/out/sampling/**`, git-ignored, incl. `buildings-12.png` that prints a rectified facade next to the game building).
* **Contain no imagery:** `tools/sampling/data/params.json` (+ `params-full.json`, `analysis.json`): colours, counts, periods, tiny bit masks: derived facts, like the heights the detail pipeline already ships. The game output of L1-L3 is procedural.

### Measuring (what exactly is sampled)
* **Rectification.** For each run an orthographic camera looks along the wall normal; a fragment shader keeps only mesh surface within a slab [-0.75, +0.5] m around the wall plane **and** whose face normal agrees (|cos| >= 0.6), so trees, cars, awnings, lamp posts in front are *cut away* rather than painted on; what is hidden stays transparent. The plane offset is found per run as the peak of the area-weighted offset histogram of near-vertical triangles (cadastre line vs mesh are within ~0.5 m); ground height per run = 12th percentile of upward triangles 0.8-4.5 m in front (restricted to |y| < 3.5).
* **Wall colour.** Median Lab of the pixels of the zone 4 m .. roofline-0.3 m after rejecting green (trees), bright blue (sky), near black; then the lightest 60 % (windows are the dark minority), then a 2-step refinement within dE < 16. Per building: length x coverage weighted median over runs; a **second colour** when runs weighing >= 22 % differ by dE > 12.
* **Illumination (important, heuristic).** The mesh textures carry the baked light of the capture day, the game applies its own light on top. Fix used: (a) per run, the colour of the pavement in front of it (sampled on the CPU from the same textures) is the illumination reference: wall / pavement x global pavement colour (brightness factor clamped 0.55-2.2, colour cast 0.8-1.25); (b) one global affine lightness map to game range (median wall L* 46 -> 78, slope 0.9, clamp 28-94); (c) gray-world white balance of 80 % of the median a*/b* offset (the baked light is cool). A sun-vs-azimuth fit explained only 6 % of the variance (`sunFit` in `analysis.json`) so no per-azimuth correction is applied.
* **Roof.** Top-down render of faces with normal.y > 0.33 above 0.5 x height, pixels inside the cadastre footprint, median Lab; class by Lab: 0 warm tile, 1 grey zinc / slate, 2 green copper, 3 dark bitumen, 4 light. Light-blue cast of the sky removed (b* +3.5), lightness floor 46 (game rule: roofs never near black).
* **Rhythm** (per run, reference run = best run >= 6 m with reliable floor and bay periods): opening mask = pixels darker than the wall by max(10, min(22, 0.22 L)); row profile -> autocorrelation (lag 2.4-7.6 m) + linear regression on row peaks = **floor height**; fold the profile by that period -> window y-start/height fractions; **ground band height** from the first window row; column profile inside window rows -> autocorrelation (1.5-9 m) + peak regression = **bay spacing**, fold -> **window width fraction**; **window-to-wall ratio**; **cornice** = blank band above the last window row; **shopfront** when the ground band openings > max(0.3, 1.5 x upper) or darker + glazed; **string course** when the vertical-gradient energy at the floor boundary phase is >= 1.7 x mean; **trim colour** = median of the ring 3 px around openings; pilasters (period as multiple of bay) when the column luminance profile has an ACF peak > 0.5 (never triggered: `pil` = 0 everywhere, treat as not detected); **bitmask** = per run, rows (ground band + floors, <= 16) x bays (<= 32), bit = opening share inside the window rectangle > 0.2 (cells with no data count as windows). Not done: balconies (the depth image `_d.png` is rendered but not analysed), rustication (`gk = 2` never produced), attic / dormer windows on mansard roofs (the game's mansard faces carry no windows).

## What was copied / changed in `buildings-s.js` (for porting; every change is marked `// [S]`)
Copied: the whole of `src/buildings.js` (imports re-pathed to `/src/..`). Changes:
1. `GeoBuilder`: four extra vertex attributes `aS1, aS2, aS3` (u8x4) and `aFac` (f32x2: bitmask slot, **bay coordinate** along the facade run); `b.ext` is set around wall quads, zero elsewhere (so every non-sampled building and every roof face is bit-for-bit the old look: level 0 is the game).
2. `wallEdgesFlat/Shape` + `facadeRuns` (`facade.js`): the two wall emitters now ask `samp.edge(k)` for per-edge colours (wall 1 / wall 2 by run), an `aWin` with floor height snapped so that **n floors fit the wall height exactly** (`U / nF`) and spacing snapped so an integer number of bays fits the run (windows are symmetric on a facade, corner piers of half a bay), and the extra attributes.
3. Pass 2: `useS` = params exist and building is not curated (landmark rule or tier-A sight; those join at L3); L1 overrides wall / roof colours (flat extrusions and shaped buildings; sight treatments are overridden too for non-curated sights), L2 overrides `winParams`.
4. Window shader: legacy window block is multiplied by `(1 - sampled)`; new `SAMPLED_GLSL` block (window rectangle with sampled width / height / sill, shop glazing or plinth in the ground band, trim-coloured surrounds, string courses, cornice band, pilaster strips, per-facade bitmask lookup in an `R32UI` data texture `uBits`, night windows reuse the existing lit-window code with the new bay / floor coordinates). Shader cache key `building-win6-samp1`.
5. `SAMP_BITS` (rows of u32 per facade) + `bitsTexture()` built at the end of `buildBuildings`.
Control: `globalThis.__SAMP = { level, params: Map(id -> record) }` (`play.html?level=0..3`).

## Parameter record and data size
`data/params.json` keys: `w` wall rgb, `w2`/`w2r` second wall colour + run ids, `r` roof rgb, `rc` roof class, `fh` floor height, `sp` bay spacing, `ww`/`wh`/`wy` window width / height / sill fractions, `gh` ground band, `gk` shop flag, `gs` glazing share, `co` cornice, `sc` string course, `pil`, `nF` floors, `trim`, `fr` per-run `{c bays, r rows, b[16] u32 mask, sp?}`.

Packed binary estimate (what the game would ship; raw bytes before gzip):
| level | bytes / building | measured set (117 buildings with params; 70 with rhythm) | whole game (17 690 buildings, if all were measured) |
| --- | --- | --- | --- |
| L1 wall + roof + class (+ second wall 4 B) | 7 (avg 8.6) | 1.0 KB | ~150 KB |
| + L2 rhythm (fh, sp, ww, wh, wy, gh, co, flags, nF, trim, pil) | +12 | +0.8 KB | +~210 KB (~ 21 B/bld) |
| + L3 bitmask, 1-2 street facades (rows x bays bits + 2 B header) | +~35 | 4.1 KB if every run is stored (418 facades, 32 B each avg) | +~0.6 MB |
JSON as written (`params.json`, 117 buildings incl. all L3 masks): 44 KB, 8.9 KB gzip; without masks 16.6 KB (142 B/bld), 3.8 KB gzip. A whole map is **0.2-0.4 MB gzip for L1+L2, ~1 MB with L3**. No pixels.

## Runtime cost in the game
Almost zero: no texture fetches, no extra draw calls. My copy adds 20 B per vertex (the game's vertex is 24 B); a port would instead pack the L1/L2 numbers into **one small RGBA8 data texture indexed by `vBid`** (the batch instance id the building shader already has: `uBld` of 2-3 texels per building = 21 B) and keep only the facade run bay-coordinate + bitmask slot per vertex (`aFac`, 8 B, or 4 B packed), plus the `R32UI` bit texture (16 x facades, 64 B per facade, ~100 KB for a map). The fragment cost is ~60 ALU ops on wall fragments and one `texelFetch` (L3); I did **not** benchmark frame time (screenshots only), so treat "~zero" as an estimate. Geometry builder cost: facade runs are an O(edges) pass per building at load.

## Results (see `scripts/out/sampling/`)
`compare-chase.png`, `compare-cab.png` (s = 1200, 1250, 1300, 1400, 1500; columns L0 | L1 | L2 | L3 | real mesh from the spike's renders), `compare-top.png` (hole game camera: Opera, boulevard, canal edge, hole radius 3 = ~58 m camera distance and 8 = ~143 m), `hero-sampled.png` (cab s = 1300, L2) with per-level frames `viewpoint-cab-1300-L0..L3.png`, `buildings-12.png` (+ `.json`: 12 evenly spaced buildings of the rhythm set: rectified real facade | game L0 | L1 | L2 with the sampled numbers; not cherry-picked), raw frames in `raw/`.

* **L1** turns the guess palettes into stone / plaster greys and the real roof greys: the red-brown and orange blocks and teal-green roofs of L0 disappear. This is the biggest win from the top-down camera (most players), because roofs fill the screen.
* **L2** adds floor and bay counts that match the real storeys, shop / ground band, cornice and light or dark surrounds; clearly visible from the tram (s = 1300, 1400, 1500), subtle from the hole camera.
* **L3** adds per-facade window patterns (blank gable walls, irregular rows) and applies the sampled colours to heroes (Opera, Stockmann, sights).

### Honest quality
* The colours are **true to the mesh photo, not to the street**: shaded facades come out cool and dull (the Stockmann block is pink-lilac in the lit courtyard facades of the mesh and brown-grey on the street side here), the baked light cannot be removed reliably; the pavement reference helps but does not fix cast shadows (e.g. the diagonal shadow on Valņu iela 26 / 30 is read as wall colour). The "white Opera" does **not** come out white: sampled wall ~ #AEB3BA (the street front is in shade in the capture), the main Opera piece (49616059) got no wall colour at all (no usable wall surface), its roof is classified grey, not copper green (the sampled grey is lighter than the game's green; at L3 it looks wrong).
* **Floors** (manual count on the rectified images, 36 of the 70 buildings that got a rhythm, single rater): 27 exact (75 %), 6 off by one (17 %: attic row counted or missed, e.g. Stockmann, Aspazijas 24 / 34, Valņu 18 / 23 / 39), 3 wrong by >= 2 or invalid (8 %: Teātra iela 12 reads 7 instead of ~5, both Opera pieces have too little wall data). So **>= 1 floor off: 25 %**, >= 2 off or garbage: 8 %.
* **Bay spacing**: in about 1 in 5 of those 36 the period locks on a multiple of the true bay (e.g. 5.3 / 6.2 / 6.4 m where the windows are ~2.6 m apart; Aspazijas 30, Valņu 35, Galerija Centrs). Window width is clamped 0.3-0.62 of the bay.
* **Coverage of the proof**: 126 buildings measured; 117 get colours; **70 (56 %) get a trusted rhythm** (the others: sheds, courtyard-only walls, tree-covered or tiny facades; gated on cover > 0.4 and ACF confidence), they stay at L1. 659 of 1431 runs yielded a usable image (the rest: no mesh surface at the wall, party walls, < 2.4 m). 6 buildings are curated heroes (L3 only).
* The second wall colour fires for 46 of 94 buildings: too eager (street front in shade vs courtyard in sun is a lighting difference, not a paint difference). A stricter threshold (dE > 20) or dropping it would be better.
* Other failure modes seen: glass facades (Stockmann, Galerija Centrs) read as grey wall with huge openings; corner buildings split into many runs (one colour per run, mostly harmless); the cadastre footprint split vs the real building (several cadastre pieces form one facade, each gets its own estimate); trees in front leave holes that are filled with "window present" in the bitmask; photogrammetry smears the ground floor (shop bands are plausible but not accurate).
* Roof classes: 68 grey, 32 dark, 13 tile, 2 copper (the Opera and the other green roofs are mostly read as grey: under-detects copper).

## Scaling to every building on the four maps (estimate, not done)
Corridor numbers (`tools/realistic`): ~0.1 km^2 (400 m x +-100 m), 648 nodes, **108 MB wire geometry + 33.5 MB JPEG = 140 MB**, i.e. ~1.4 GB / km^2 at that LOD (geometry dominates; the textures alone ~335 MB / km^2). Maps: centre 5 276 buildings (box 8.9 km^2, mesh covers 84 % of the buildings), Āgenskalns 7 165 (6.8 km^2, 55-82 %), Mežaparks 1 870 (6.8 km^2, 71-98 %), **Purvciems 3 379 (6.8 km^2, only 15-18 % of the buildings have mesh, ~600)**. Built-up share ~60-80 %: ~20-25 km^2 of useful tiles -> **~30 GB wire (~7 GB of it textures)** at the corridor LOD; Purvciems adds only ~1 GB because the mesh is missing there (the panel blocks would stay on the game's palette). The tile server is a third-party ArcGIS service, ≤ 4 concurrent requests, 5-10 MB/s sustained is optimistic: **2-6 h of polite downloading in total**, then the measurement is cheap (this run: 8 s GPU + ~20 s node for 126 buildings; ~15-30 min for 17 000 buildings if tiles are streamed through, memory ~1 GB per 0.1 km^2 tile batch). Wall measurement needs the fine nodes (mean edge ~0.3 m); the 1 m geometry of the detail cache is not enough for facades. Re-running when the cadastre / shapes change is cheap but the facade-run indices are tied to the edge geometry (store a hash).

## Recommendation
* **Ship L1 + L2** (sampling), as a data file of ~0.3 MB gzip for the game, after fixing: the white-balance / exposure heuristic per map, a stricter second-wall rule, and a confidence gate (use rhythm only where cover and ACF confidence are good, as here). L1 alone is the cheapest and already removes the worst mismatches (orange / brown blocks, teal roofs); L2 is what makes the tram view read as Riga.
* **L3 bitmasks**: nice on irregular facades and gables but costs per-facade data and a shader texture, and the measured masks are noisy; do it only for the ~100 most visible facades (tram routes, sights), or skip.
* **Hero buildings (Opera, Stockmann)** need curated colours: sampling does not give "Opera white" (shade, glass, copper roofs).
* What **texture baking still adds** on top of sampling: ornament (pediments, columns, balconies, rustication, statues), shopfront detail, true colours of lit facades (no de-lighting guesswork), per-building weathering, and the recognisable silhouette of facades like the Opera portico (geometry, not texture). Sampling cannot do any of that; it removes the "all beige boxes" look cheaply and safely, baking is the next step if the municipality agrees in writing.

# v2 (centre map, gated L1 + L2): what changed and what the numbers are

Order of work: colour pipeline fixes, roof material-first, strict second colour, rhythm gates, then the whole-centre run (`plan.mjs`, `measure2.html`, `analyze2.mjs`, `validate.mjs`, `pack.mjs`, `shots2.mjs`, `sheets2.mjs`, `realtop2.mjs`, `meshview2.html`), porting notes in `PORT.md`. Outputs: `scripts/out/sampling/v2-*.png`, `tools/sampling/data/params-centrs.json` (+ `.bin`, `.full.json`, `analysis-centrs.json`, `validation-centrs.json`, `floor-labels.json`).

## Download (centre)
Plan `node tools/sampling/plan.mjs 0.4`: all layers over the centre box, nodes that touch a building footprint (dilated 5 m, sheds < 5.5 m dropped) with estimated vertex spacing <= 0.4 m: **6 661 nodes, 194 M vertices, ~2.6 GB geometry wire + ~0.2 GB textures**, of which 2 474 geometry files and 1 163 textures were already on disk (the other agent's `tools/.cache/realistic`, the detail cache; read only). **Fetched 9 685 files = 1 799 MB wire (4.1 GB raw) in ~12 minutes, 0 failures**, 4 concurrent, backoff, resumable, into `tools/.cache/sampling/i3s/`. Other spacings for reference (missing volume): 0.5 m 0.6 GB, 0.3 m 4.3 GB, 0.2 m 9.8 GB. My earlier "1.4 GB / km2" was too pessimistic for a footprint-only selection: the centre needs ~2.8 GB in total (1.4 GB / km2 of built ground, 4.4 km2), so **~8-10 GB for all four maps** (Purvciems far less: no mesh for ~85 % of it). Measurement: 3 731 buildings, 26 712 facade images, 3 731 roofs in 219 s on the GPU (streamed in 220 m cells); analysis ~8 min on one core.

## Colour pipeline v2
* Wall colour = **brightest-lit consistent sample** (non-opening pixels with L between the 60th and 92nd percentile of the wall), not the median.
* Illumination: the pavement in front of each facade (brighter half of its texels) is the reference, smoothed with same-facing runs within 70 m (50 %), per-channel cast removal limited to 0.8-1.25, albedo = wall / pavement x 0.32 (albedo of the reference pavement, the one calibrated number, together with a plaster prior: scale, not clip, to a max channel of 0.72; soft clip of blue casts below b* = -3 with factor 0.2). **This is a heuristic**: a sunlit pavement in front of a shaded wall (or the reverse) still gives a wrong exposure (the Opera comes out pale blue-lilac instead of cream).
* Validation 1 (**same building, two facades of different orientation, which must have the same paint**; 22 533 pairs, includes genuinely different facades, so it is an upper bound): residual dE median / p80: raw median 15.4 / 29.5, bright-sample only 15.5 / 28.9, bright + pavement 13.9 / 23.1 (the first version of the pavement correction made it WORSE, 18.6, until the reference was smoothed and the gain clamps fixed).
* Validation 2 (`v2-swatches.png`, 20 buildings with expectations written from my own knowledge, confidence 1-3, **the owner should veto any row**; 12 of them have wall data; Melngalvju nams, both art buildings, the Dome, the Town Hall, the Nativity cathedral and St Peter's have none because their cadastre / shape edges give no usable wall surface): median dE76 to the expected wall colour: **raw v1 48.6, bright-only 43.4, final 19.8** (calibration half of the list 30.1, held-out half 17.9, the single calibrated parameter is the pavement albedo 0.32); lightness bias -2.6; sampled chroma is **57 % of the expected chroma** (mean saturation too low; boosting it with a global gain (tested 1.6-3x) did not reduce dE, so it was NOT boosted; hue errors and shade / sun mismatch dominate). Worst rows: Trīs brāļi (middle, yellow) 37, Pulvertornis 37, Rīgas pils 30, Nacionālais teātris 31, Kaķu nams 28, Nacionālā opera 20. Best: Hotel Latvija 6, Splendid Palace 7, LU 11, eldest brother 13.
* Verdict on the swatch sheet: the pipeline now gives **light warm plaster-like colours** (median wall Lab 78 / 3.5 / 5.6, i.e. cream), no more mid-grey slabs, but it does not reproduce saturated paint (yellow, ochre, brick red come out cream / peach) and it fails where the wall sits in shade next to sunlit ground. In the game's own lighting the shaded side of a street still renders brown-grey (the sampled albedo of those blocks is pale cream, e.g. Valņu iela 30 (222,202,175), Aspazijas 34 (221,211,199)): that darkness is the game's sun / hemisphere model, not the sample.

## Roofs (material first)
Class from the lit texels (warm share, green share, lightness) then the colour from the class range (see PORT.md section 4). Centre: tile 783, zinc/grey 2 295, copper 418, bitumen 112, light 20. **Old Town (538 roofs): 43 % tile on evidence, 85 % with the owner prior (the shipped file uses the prior); the rest of the centre 14 % tile.** Copper is under-detected on the Opera (its roof reads grey-brown if the sample is used; curated heroes keep their own roof colour). The orthophoto measurement quoted in `buildings.js` (17-25 % red, 70-78 % grey in the Old Town) agrees with the mesh, not with the game's 90 % tile: that is a style decision for the owner.

## Second colour, rhythm
* Second wall colour only when two facade groups differ by dE > 18 after correction, each group well measured (cover > 0.4, not shaded), >= 25 % of the weight and >= 8 m: **496 buildings (13 %)**, was 49 %.
* Ground band: faint plinth, light glazing, mix 0.5 (no black stripe). Bay spacing: if the profile repeats at half the period (ACF >= 0.6 of the first) the half is taken (>= 1.7 m).
* **Floors, fresh hand check**: 40 random centre buildings (seeded, `floor-labels.json`), me counting window rows above the ground band on the rectified image, single rater: **24 exact (60 %), 9 off by one (22.5 %), 7 wrong by >= 2 or facade unusable / blank gable (17.5 %)** (corridor sample earlier: 75 / 17 / 8). Extra gates added afterwards (>= 2 detected rows, window ratio >= 0.08, floor height 2.8-5.6 m, row count within 1 of the geometric floor count, bay confidence > 0.25) keep 20 / 24 exact, 9 / 9 off-by-one, only 3 / 7 bad, i.e. among the 32 that pass: 62 % exact, 28 % off by one, 9 % bad (gates tuned on the same 40: optimistic). Centre rhythm after gating: **1 250 buildings (33 % of the measured, 24 % of all)**. Bay spacing locked on a multiple in about 1 in 5 before the half-period rule (not re-counted).

## Coverage and size (centre)
5 241 buildings in the game; measured 3 731 (sheds < 5.5 m and small aux dropped); shipped records 3 598: wall colour 3 097 (59 % of all), roof 3 454 (66 %), rhythm 1 250 (24 %), second wall 496. **params-centrs.bin 49 218 B (13.7 B/building), 40.7 KB gzip**; json 413 KB / 76 KB gzip. ## Is it good enough to ship?
**Partly. Roofs and the removal of the wrong palette (orange / teal / red-brown blocks) are a clear improvement and safe (L1, gated). Wall colours are better (dE 48 -> 20) but not true; rhythm is a soft gain with ~40 % of buildings off by at least one floor, ~10-18 % visibly wrong (blank gables, tiny facades).** I would ship L1 (roofs + walls, gated) now behind the owner's veto of the Old Town roof prior, and L2 only for the ~1 250 gated buildings with the dirty cases (gables, fh outside 2.8-5.6 m) excluded as done. I would NOT claim it solves "dull": the city reads greyer than the old palette (zinc roofs dominate, as in reality) and the heroes seen first from the tram (Opera, Stockmann) are untouched.
